# 02 · 视频复刻流程与技术框架

## 一、视频里到底做了什么（流程还原）

视频演示的是"用 AI 编程工具从零做一个个人作品集站"的完整链路，共 5 步。下表还原每一步的**实际动作**与**可复用方法**：

| 步骤 | 视频中的动作 | 方法要点 | 在本项目中的对应实现 |
| --- | --- | --- | --- |
| **01 起步** | 打开 Codex，输入一句话："帮我做一个高级的个人网站" | 先要一个**能跑起来的最小版本**，不要一次描述全部细节 | `npm run dev` 直接出可预览站点，先跑通再迭代 |
| **02 立结构** | 提供一段结构化提示词：身份 / 站点基调 / 页面模块清单 / 技术栈 / 版心宽度 | 提示词按"身份 → 基调 → 模块 → 技术约束"四段写，模块用编号列表 | 见下方"结构化提示词模板"，本项目按此产出 |
| **03 找参考** | 打开参考站（视频里是 awwwards 类作品集、DESIGN SUPERPOWERS 等）截图，让 AI 照着做 | 用**真实站点截图**替代形容词，"高级感"才能落地 | 采用深色 + 中性色 + 大字号标题的编辑型排版语言 |
| **04 加动效** | 打开 ReactBits，挑组件，看右侧参数面板，调整后复制代码 | ReactBits 每个组件都有可调参数（颜色 / 幅度 / 速度），先调后取 | 本地化 7 个 ReactBits 组件，参数全部外置为可配置项 |
| **05 逐模块打磨** | 对话式改：改标题体系 → 统一字号 → 背景应用 → 模块逐个优化 | 一次只改一个维度，改完立刻看效果 | 样式令牌集中管理，改一处全局生效 |

### 结构化提示词模板（可直接复用）

```
根据我的简历，请从零搭建一个个人作品集网站。

我的身份是数据分析师（商业分析 / BI 方向），1.5 年经验，统计学背景。
网站整体是深色系、中性色、克制、有秩序感，不要像模板站。

页面需要包含：
1. 全屏首页 Hero：大标题、定位一句话、导航栏、联系按钮
2. 个人档案模块：证件照、个人介绍、联系方式、4 个量化数据
3. 工作经历模块：时间线形式，含教育
4. 精选项目模块：大卡片展示项目，含背景 / 做法 / 结果
5. 个人优势模块：4 张卡片展示能力
6. 底部联系方式：整屏收尾页

技术要求：
- React + Vite，版心控制在 1200px 左右
- 动效克制，仅用于入场与悬停，不干扰阅读
- 所有内容集中在一个数据文件，方便替换

先完成一个可运行、可预览的基础版本。
```

> **视频里最有价值的一句**：先做一个"能看的基础版"，再逐模块优化。一次性描述越细，返工越贵。

## 二、本项目的技术框架

### 2.1 技术选型与理由

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 构建 | **Vite 5** | 冷启动 < 1s，产物小，静态部署零配置 |
| 框架 | **React 18** | ReactBits 组件原生基于 React，直接复用无需改写 |
| 语言 | **JavaScript (JSX)** | 降低手改门槛：非专业开发者也能读懂 `resume.data.js` |
| 样式 | **原生 CSS + CSS 变量** | 不引入 Tailwind，避免类名噪音；令牌化后改一处全局生效 |
| 路由 | **无路由（单页滚动）** | 简历站不需要多页；减少状态复杂度，分享链接永远指向完整页面 |
| 状态 | **React Context + localStorage** | 无后端；编辑结果本地持久化，可导出 JSON 迁移 |
| 动效 | **ReactBits 本地化组件 + CSS** | 复制源码而非装 npm 包，避免版本漂移与依赖风险 |
| 图形 | **Canvas / SVG / CSS** | 零额外依赖，可控性能 |

### 2.3 三层数据流（这是"可维护"的关键）

```
        ┌─────────────────────────────────────┐
        │  resume.data.js  ← 唯一内容源        │
        │  （文案 / 图片 / 链接 / 模块开关）    │
        └──────────────┬──────────────────────┘
                       │ 默认值
                       ▼
        ┌─────────────────────────────────────┐
        │  ResumeProvider  ← 运行时状态        │
        │  localStorage 覆盖默认值（增量合并）  │
        └──────────────┬──────────────────────┘
                       │ context
        ┌──────────────┴──────────────┐
        ▼                             ▼
   sections/*（渲染）            editor/*（编辑）
```

**设计要点**：`resume.data.js` 永远是"出厂默认值"。用户在页面上改的内容写入 `localStorage` 作为**覆盖层**，不污染源文件。点"恢复示例内容"即清除覆盖层。这样既能改，又不会把项目改坏。

### 2.4 视觉系统（中性 + 深色）

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--bg` | `#0B0C0E` | 页面底色（近黑，带一点冷灰） |
| `--bg-elev` | `#121417` | 卡片 / 面板 |
| `--bg-elev-2` | `#191C20` | 悬浮 / 输入框 |
| `--line` | `rgba(255,255,255,.09)` | 分隔线、描边 |
| `--text` | `#ECEDEF` | 主文字 |
| `--text-dim` | `#9BA1A8` | 次级文字 |
| `--text-mute` | `#6B7178` | 辅助 / 标签 |
| `--accent` | `#B8C4A8` | 主强调（低饱和橄榄灰，非荧光） |
| `--accent-2` | `#C9A227` | 次强调（琥珀，用于数据高亮） |

**为什么不用亮绿 / 电光蓝**：视频里的荧光绿是视觉设计师的自我表达；数据分析岗面向 HR 与业务负责人，克制的中性色更能传递"严谨、可信"。强调色只用于**数据与可点击项**，不用来装饰。

**字体**：标题用 `Instrument Serif`（衬线，编辑感、非 Inter），正文用 `Inter Tight` 或系统无衬线；数字与代码用 `JetBrains Mono`。三款字体全部本地自托管回退，避免外链阻塞。

> 若需完全离线，删除 `@import` 后回退到系统字体栈，视觉降级但可用。

### 2.5 动效清单（性能优先）

| 组件 | 来源 | 用在哪 | 性能策略 |
| --- | --- | --- | --- |
| `Aurora` | ReactBits | Hero 背景 | Canvas，`dpr` 封顶 1.5，页面不可见时 `cancelAnimationFrame` |
| `DotGrid` | ReactBits | 全局背景纹理 | 静态 SVG pattern，零 JS |
| `SplitText` | ReactBits | Hero 大标题 | 仅入场一次，`prefers-reduced-motion` 时直接显示 |
| `CountUp` | ReactBits | 量化指标 | `IntersectionObserver` 触发，只跑一次 |
| `SpotlightCard` | ReactBits | 项目 / 能力卡 | `pointerenter` 才绑定 mouse 事件，移动端禁用 |
| `TiltedCard` | ReactBits | 项目大卡 | 仅 `hover: hover` 设备启用 |
| `ScrollReveal` | ReactBits | 各模块入场 | 统一 `IntersectionObserver`，避免每组件一个 |

**稳定性红线**：
1. 所有动画组件在 `prefers-reduced-motion: reduce` 下退化为静态。
2. Canvas 组件在 `document.hidden` 时暂停。
3. 移动端（`< 768px`）关闭 3D 倾斜与光标跟随。
4. 不使用 `scrollIntoView`（iframe 预览会破坏外层滚动）。
5. 首屏 LCP 目标 < 2.5s：字体 `font-display: swap`，首屏图片不超过 1 张。

## 三、模块化系统设计

### 3.1 框架约束（哪些能动、哪些不能动）

| 模块 | key | 位置 | 可移除 | 小模块上限 | 说明 |
| --- | --- | --- | --- | --- | --- |
| 首屏 | `hero` | **锁定首位** | ✗ | 3 个行动按钮 | 站点第一印象，移除即失焦 |
| 个人档案 | `profile` | 中部可调 | ✓ | 6 个信息字段 / 4 个指标 | 必展示信息集中于此 |
| 工作经历 | `experience` | 中部可调 | ✓ | 6 段 | 时间线 |
| 精选项目 | `projects` | 中部可调 | ✓ | 6 个 | 大卡 |
| 个人优势 | `capabilities` | 中部可调 | ✓ | 6 张 | 能力卡 |
| 联系方式 | `contact` | **锁定末位** | ✗ | 4 个联系项 | 收尾整屏 |
| 自定义模块 | `custom-*` | 中部可调 | ✓ | 每种类型 4 个子块 | 自由新增 |

**位置调整规则**：中部模块通过上移 / 下移按钮调整顺序；首位与末位锁定。这是"框架限制"的具体含义——保证站点始终有开头和收尾。

### 3.2 三种自定义模块类型

| 类型 | 用途 | 子块字段 |
| --- | --- | --- |
| `richText` | 自由文本（补充说明、教育、证书、自我评价） | 标题 + 段落（支持简单换行） |
| `gallery` | 图文混排（作品图、图表截图、证书照片） | 图片 + 标题 + 说明，4:3 统一裁切 |
| `linkGrid` | 链接集合（GitHub、博客、知乎、公众号） | 名称 + URL + 一句话说明 |

### 3.3 编辑与分享闭环

```
打开站点
   │
   ├─ 浏览模式：看示例内容
   │
   └─ 点击右上"编辑" → 进入编辑模式
          │
          ├─ 改文案：右侧面板逐字段改，实时生效
          ├─ 换证件照：上传 → 4:3 裁剪 → 压缩（≤5MB，实际约 300KB）
          ├─ 加模块：选择类型 → 填写 → 保存（上限内）
          ├─ 调顺序：上移 / 下移（首末锁定）
          ├─ 换配色：4 套预设 + 自定义强调色
          │
          └─ 保存 → 写入 localStorage（自动）
                 │
                 ├─ 导出 JSON：备份 / 迁移 / 发给别人
                 └─ 导入 JSON：恢复
```

**"分享给别人填自己的内容"怎么实现**：
1. 对方打开同一站点 → 点"清空为空白模板" → 填入自己的内容 → 导出 JSON 保存。
2. 数据不离开浏览器，无需账号、无隐私风险。
3. 若需生成一条可发送的链接，使用"复制内容链接"（内容压缩进 URL hash，**仅适合纯文本内容**，含图片时请用 JSON 导出）。

> 明确不做的：云端存储、多人协作、账号系统。这些需要后端，超出"静态分享"的必要范围，也带来隐私责任。

## 五、风险与边界（诚实说明）

| 风险 | 影响 | 处理方式 |
| --- | --- | --- |
| 字体外链失败 | 首屏字体降级 | `font-display: swap` + 完整回退栈，不阻塞渲染 |
| localStorage 被清 | 编辑内容丢失 | 提供 JSON 导出，README 明确提醒定期备份 |
| URL hash 分享含图片 | 链接过长或被截断 | 文档中明确：含图片只用 JSON 导出 |
| ReactBits 组件后续版本变化 | 升级可能不兼容 | 源码已本地化，不随上游变动；不升级即稳定 |
| 证件照过大 | 首屏变慢 | 强制 4:3 裁剪 + 压缩到 ≤400KB，原图不入库 |
| 移动端 3D 动效耗电 | 掉帧 | `<768px` 或 `hover: none` 时全部禁用 |

## 六、与"纯手写简历"的差异（为什么值得做）

1. **可验证**：项目结论带基线与终值，招聘方点开就能看到分析思路，比 PDF 里一行"负责数据分析"有信息量。
2. **可维护**：换岗位只改 `resume.data.js`，不动组件；比重新排版 PDF 快。
3. **可复用**：同一套框架能给别人用（空白模板 + JSON 导入），一次投入多处产出。
4. **有取舍**：主动不放"兴趣爱好""自我评价"，是因为招聘方在 30–90 秒内只关心"能不能干这个岗"。
