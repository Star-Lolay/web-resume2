# 05 · 动效系统与单文件导出

本文档说明两件事：

1. 首屏到页尾的动效是怎么组织、怎么改颜色、怎么关掉的
2. 「改完自己的内容和配色，导出一个独立网站」这个功能怎么用、原理是什么

---

## 一、动效的分层编排

### 1.1 整体结构

动效不是几个一起常驻跑，而是**按页面位置分段挂载**。

判断依据不是「滚动百分比」，而是**真实 DOM 测量**——因为模块可以增删、可排序，用百分比会把动效切在错误的地方。具体做法是量最后一个 `<section>` 的绝对顶端，据此推出「最后一屏从哪开始」。

| 位置 | 显示什么 | 组件 |
| --- | --- | --- |
| 首屏（0 → 1 屏高） | 3D 纵深网格走廊 + 扫描光带 | `GridScan` |
| 首屏之后 → 最后一屏之前 | 方块流动墙（个人档案 / 经历 / 项目 / 优势 / 自定义模块） | `MicroSlats` |
| 最后一屏 | 星野（sparkle 星点 + 光晕） | `Galaxy` |
| 最后一屏底部 | 一小块白色流动柔光 | 纯 CSS（不占 WebGL） |
| 首屏延迟 0.5 秒 | 环形图片，绕轨道缓慢旋转 | `OrbitImages` |
| 亮色主题全程 | 虹彩纸面质感（唯一动效层） | `Iridescence` |

### 1.2 三段是怎么衔接的

不是硬切，而是用 `smoothstep` 对不透明度做交叉淡入淡出：

```
首屏 ──GridScan 淡出──┐
                      ├── 重叠约 0.14 屏高，视觉上连续
中段 ──MicroSlats 淡入─┘

中段 ──MicroSlats 淡出──┐
                        ├── 最后一屏进入时交叠
收尾 ──Galaxy 淡入──────┘
```

`GridScan` 的高度锁死在 `100vh`（不是 `100%`），滚过一屏它就完全不在视野里——这是「纵深方框只出现在第一页」的实现方式。

首屏底部用 `mask` 渐隐衔接，不是靠压一层暗色遮罩，所以不会出现「一块阴影」。

### 1.3 为什么这么设计

多个 WebGL 着色器同时跑会明显掉帧，而且显卡上下文有配额。分段挂载带来两个好处：

- 任意时刻最多 1 个主体 canvas，帧率稳定
- 上下文丢失只会影响当前这一段，其余层不受牵连

### 1.4 参数与颜色的来源

**所有参数集中在 `src/content/effects.config.js`**，这是唯一来源。

官网 URL 参数（来自 ReactBits）已经展开成真实组件入参，对应关系在文件里逐条注释了。要注意：官网 URL 里的 `preset=pulse` / `preset=storm` / `preset=sparkle` 是**官网自己的预设名**，组件本身没有 `preset` 入参——配置里写的是展开后的真实值。

想改颜色，改这几个字段：

| 效果 | 颜色字段 | 说明 |
| --- | --- | --- |
| GridScan | `scanColor` | 扫描光带颜色（默认粉 `#f7b5c5`） |
| GridScan | `linesColor` | 网格线颜色 |
| MicroSlats | `color` / `glintColor` | 板条基色 / 高光色 |
| Galaxy | `starColors` | 星点色数组（最多 4 个） |
| edgeGlow | `colors` | 底部白色流光的三段色 |
| Iridescence | `color` | 亮色主题的虹彩基色 |
| OrbitImages | `pathColor` | 轨道线颜色（默认不显示） |

想换环形图片，改 `orbitImages.images` 数组，指向 `public/` 下的文件或任意外链。

### 1.5 一处为了可读性做的妥协

`MicroSlats` 这组参数（`contrast=1.8` / `glint=1.3`）本身会让部分板条冲成接近纯白，叠在正文上形成棋盘格。参数是需求指定的不能改，所以从「层」这一级调权重：

```css
filter: brightness(1.6) contrast(0.92) saturate(0.85);
mix-blend-mode: screen;
```

这组值不是拍脑袋定的。实测（1440×900 中段截图，取平均亮度与像素标准差）：

| 配置 | 平均亮度 | 对比度(sd) |
| --- | --- | --- |
| 关闭该层（参照） | 24.8 | 17.4 |
| 原始遮罩方案 | 31.5 | 19.5 |
| **当前方案** | **35.2** | **18.9** |

也就是「更亮，但更柔和」——亮度提上去了，方格感反而更弱。

### 1.6 在页面上改，不用改代码

打开右上角设置面板（齿轮图标），有「动效配色」和「动效开关」两组：

- 配色改动**实时生效**，并自动存 `localStorage`
- 每个效果都能单独关掉，关掉后该段自动退回静态渐变背景，不留空档
- 「恢复动效默认配色」一键回到出厂值

### 1.7 两种会自动降级的情况

- **亮色主题**（`paleAsh`）：不再分段切换，全程固定 `Iridescence` 虹彩层。原样铺满会变成彩色壁纸，所以做了三层收敛：`multiply` 混合 + 降饱和（0.5）+ 不透明度 0.34。同时亮色令牌（`tokens.css`）按 WCAG AA 收紧，正文对比度约 14.8:1。
- **移动端**（< 900px）：重动效默认关闭（`perf.enableOnMobile = false`），只留静态渐变和底部 CSS 流光，省电且更流畅。

## 二、单文件导出

### 2.1 它是什么

把当前站点的**全部内容 + 配色 + 动效配置**打包成**一个 `.html` 文件**。

双击就能打开，不需要服务器、不需要部署、不需要联网（字体除外，断网时回落到系统字体）。可以发给别人，也可以自己留档。

### 2.2 怎么用

1. 在页面上编辑内容（「编辑」按钮），改动会实时保存
2. 打开设置面板（齿轮），调好配色主题与动效配色
3. 点「导出 → 导出为单文件网页」
4. 点「生成并下载」，得到 `你的名字.html`

导出的文件里**不含编辑器和设置入口**——成品是给人看的，不是给人改的。

### 2.3 成品里包含什么

| 内容 | 处理方式 |
| --- | --- |
| 简历正文 | 作为 `window.__RESUME_BOOT__` 注入，启动时优先读取 |
| 配色主题 / 动效强度 | 同上，写进 boot，保证成品与调好的效果一致 |
| 动效配置（含颜色） | 同上，整份完整配置 |
| 模块顺序 / 隐藏状态 | 同上 |
| 图片（头像、环形素材、自定义图） | 全部转 data URL 内联 |
| CSS / JS | 原样内联构建产物 |
| 字体 | 走 Google Fonts 外链（联网生效，断网回落系统字体） |

### 2.4 为什么能「双击打开」

关键在于构建产物是**单个 IIFE bundle**：不含 `import.meta`、不含 `export`、不含动态 `import()`。

因此可以内联成普通 `<script>` 而不是 `<script type="module">`——后者在 `file://` 下会被 CORS 拦掉。这一点已经核实过产物，不是猜测。

### 2.5 实现上踩过的两个坑

**坑一：开发服务器会把未命中路径回退成 index.html**

`fetch('/standalone/app.js')` 在 dev server 下会返回 **200 + 一整页 HTML**。只看 `res.ok` 就会把 HTML 当 JS 内联，生成一个 20KB 的假成品。

解决：`fetchAsset()` 校验响应首字符，以 `<` 开头的一律判为无效。

也正因如此，**导出功能只在构建后的版本可用**——`npm run build` 之后用 `npm run preview` 或线上站点，dev server 下会给出明确提示而不是生成坏文件。

**坑二：成品里 boot 被 localStorage 绕过**

最初 `effectsOverride` 的初始值无条件读 localStorage，成品拿到 `{}`，于是 `resolveEffects({})` 只返回默认值，boot 里的完整配置被完全忽略——表现是环形图仍去请求 `/orbit/xxx.svg` 而不是内联的 data URL。

解决：初始化时先判断有无 `window.__RESUME_BOOT__`，有就直接用 boot 的完整配置。

### 2.6 构建流程的一个额外步骤

`npm run build` 现在是两步：

```
vite build                        → dist/assets/index-<hash>.js
node scripts/make-standalone.mjs  → dist/standalone/app.js（固定文件名）
```

导出功能要 fetch 自己的 bundle，但 Vite 产物名带内容哈希、源码一改就变，所以额外复制一份固定名字的副本供导出使用。哈希版照常留给站点自身（可长期缓存）。

### 2.7 体积参考

当前导出成品约 **460 KB**（bundle 382 KB + 内联图片）。图片越多、越大，成品越大；单张图片建议压缩后再用。

### 2.8 边界说明

- 成品是**只读**的：在里面编辑内容不会保存（不写 localStorage），刷新即恢复
- 成品**不含**「生成子网站」那种云端托管能力——它就是一个文件，不需要服务端。如果需要在线链接，把文件上传到任意静态托管即可（GitHub Pages、Cloudflare Pages、对象存储）
- 微信等内置浏览器打开本地文件可能受限，建议用系统浏览器

## 三、文件索引

| 文件 | 职责 |
| --- | --- |
| `src/content/effects.config.js` | 动效参数与颜色的出厂默认值 |
